### 2.19 其他选型速答表（被顺口问到时的 30 秒回答）

> **这一节的作用**：面试官不会逐个问你所有依赖，但会**顺口抽查**几个。下面每一项都按「**它是什么 → 为什么用它 → 替代方案与不选的原因 → 代价**」备好，答完就停，不要展开。

#### 数据访问层：Spring Data JPA（Hibernate）

- **是什么**：把 Java 对象和数据库表映射起来（叫 ORM），你写 `findByUserIdOrderByStartTimeDesc` 这样的方法名，框架自动生成 SQL。
- **为什么用它**：本项目实体关系简单、以单表增删改查为主，JPA 的 Repository 能省掉 90% 的样板代码；配合 `@Transactional` 声明式事务，事务边界和 Service 方法边界一致。
- **替代方案**：
  - **MyBatis / MyBatis-Plus**：SQL 完全可控、便于做复杂查询和分页调优，但要手写 XML 或注解，且实体与 SQL 双份维护。**不选的原因**：本项目没有复杂联表查询，用 MyBatis 属于自找麻烦。
  - **JOOQ**：类型安全的 SQL DSL，编译期检查最强，但学习成本和构建复杂度高。
- **代价**：复杂查询会失控（N+1、隐式全表加载）；**数据库方言绑死**，这也是我集成测试只能用 H2 的原因之一。

#### 对象转换：MapStruct 1.6.3

- **是什么**：一个**编译期**生成 DTO ↔ Entity 转换代码的注解处理器（不是运行时反射）。
- **为什么用它**：`AGENTS.md` 规定"禁止直接把 Entity 返回给前端"，那就有大量 Entity→DTO 的转换。反射方案（`BeanUtils.copyProperties`）**字段改名后编译不报错、运行时静默给 null**；MapStruct 生成的是普通 Java 代码，字段不匹配**编译期就失败**。
- **替代方案**：手写 setter 转换（代码量爆炸）、BeanUtils 反射（上面说的静默失败）。
- **代价**：多一个注解处理器，首次全量构建变慢几百毫秒；IDE 需要开启注解处理，否则会看到"实现类找不到"的报错。

#### 减少样板代码：Lombok 1.18.36

- **是什么**：编译期生成 getter/setter/构造器/日志字段的注解库（`@Getter`、`@RequiredArgsConstructor`、`@Slf4j`）。
- **为什么用它**：173 个 Java 文件里绝大多数是实体和 DTO，手写访问器会淹没真正的业务逻辑。
- **代价**：IDE 需要插件；**和 MapStruct 的注解处理器有先后顺序问题**（Lombok 必须先跑），版本升级时踩过坑，所以两个版本号我都在 `gradle/libs.versions.toml` 里锁死了。

#### 接口文档：SpringDoc OpenAPI 3.0.2

- **是什么**：扫描 Controller 自动生成 OpenAPI（Swagger）文档并提供可交互的调试页面。
- **为什么用它**：项目有 6 个模块、几十个 REST 接口，**没有文档我自己都会记错参数**；而且它能直接从 `@Valid` 的 Request 类里推出请求体结构。
- **替代方案**：手写 Markdown 接口文档——**必然和代码漂移**，这正是我在别的文档上踩过的坑（`docs/voice-interview-architecture.md` 里的参数值就和 `application.yml` 不一致）。
- **代价**：会额外暴露接口结构，**生产环境应该关掉或加鉴权**——这是一个我应该补但还没补的点。

#### 响应式依赖：Reactor / WebFlux（只用在流式接口，不是全站响应式）

- **是什么**：Reactor 是 Java 的响应式流实现，`Flux<T>` 表示"未来会陆续到达的一串数据"。
- **为什么用它**：**SSE（Server-Sent Events）流式问答**必须一边生成一边推，不能让客户端等全部生成完。项目里只有两个地方用到：`KnowledgeBaseController.java:106` 的 `Flux<String>` 和 `RagChatController.java:116` 的 `Flux<ServerSentEvent<String>>`，底层都由 `KnowledgeBaseQueryService.answerQuestionStream(...)`（`KnowledgeBaseQueryService.java:192/204`）产出。
- **必须说清的一点（避免被追问翻车）**：**这不是一个响应式项目**。主框架是 Spring MVC（阻塞式、虚拟线程扛并发），WebFlux 只是为了让 MVC 能返回流式响应而引入的 Reactor 依赖。面试官问"你项目是响应式的吗"，正确回答是"**不是，只有流式问答那一个出口是 Flux**"。
- **代价**：MVC 和 Reactor 混用时要小心线程模型——流式回调可能跑在别的线程上，所以我在流式路径里**不碰事务和 ThreadLocal**（这也是"禁止在事务方法里调外部 API"这条规范的另一个理由）。

#### 中文文件名处理：pinyin4j 2.5.0

- **是什么**：把汉字转成拼音的库。
- **为什么用它**：用户上传的简历文件名大概率是中文（"张三-后端-Java开发.pdf"）。**对象存储的 key 直接用中文要处理 URL 编码、部分 S3 兼容实现的编码行为还不一致**（我开发用 MinIO、又试过 RustFS，两家的编码表现不完全一样）。
- **本项目的实现**：`FileStorageService.generateFileKey(...)`（`FileStorageService.java:208`）生成 `前缀/日期/uuid前8位_安全文件名`；`sanitizeFilename` → `convertToPinyin`（`:225-259`）把汉字转成首字母大写的拼音、其余非法字符统一替换成下划线（`sanitizeChar`，`:264`）。
- **替代方案**：直接用 UUID 当文件名（**丢失可读性**，运维排查时完全不知道这个文件是谁的）、直接存中文（编码风险）。
- **代价**：拼音转换是**逐字符多音字随便取第一个读音**的（`:249` 取 `pinyins[0]`），"重庆"可能变成 `ZhongQing`。只影响可读性，不影响正确性。

#### 测试数据库：H2 内存库

- **是什么**：纯 Java 的内存数据库，跑测试时不用起真实 PostgreSQL。
- **为什么用它**：`application-test.yml` 里配 `jdbc:h2:mem:testdb` + `ddl-auto: create-drop`，测试**启动快、无外部依赖、每次跑都是干净库**。
- **代价（必须自己先说，这是真短板）**：H2 **没有 pgvector 类型**，所以向量检索的 SQL 根本跑不了——测试配置里只能把 `spring.ai.vectorstore.pgvector.initialize-schema` 设成 `false`，知识库的向量服务测试**全部是 mock 掉 VectorStore 的单元测试**，真实 SQL 一条都没验证过。
- **正确做法**：用 **Testcontainers** 起一个真的 `pgvector/pgvector:pg16` 容器跑集成测试。**我目前没做**（项目里 grep 不到 Testcontainers），这是我知道的第一优先级补齐项。

#### 我没有用 Flyway / Liquibase（数据库版本管理）

- **现状**：表结构由 Hibernate 的 `ddl-auto` 管（开发 `update`，生产 `false`），`resources` 下**没有 `db/migration` 目录**。
- **代价**：`ddl-auto: update` 只会加列、**不会删列也不会改类型**，而且没有版本化脚本 → **没法做可控的生产迁移、没法回滚**。项目文档里还留着一个指向 `db/migration/` 的失效链接，正好说明文档写的是"计划"而不是"现状"。
- **正确做法**：引入 Flyway，把每个版本的 DDL 写成 `V1__init.sql`、`V2__add_pgvector.sql` 这样的编号脚本，`ddl-auto` 设成 `validate`。

#### 我没有做鉴权（最该主动交代的一条）

- **现状**：项目**没有引入 Spring Security，也没有 JWT / Sa-Token**。全项目搜 `Authorization` 只命中一处，是调用大模型时**往外发**的请求头（`LlmProviderConfigService.java:820`）。
- **用户隔离是怎么做的**：实体里有 `user_id` 字段，但**当前是写死的占位值**——`VoiceInterviewService.java:58` 定义 `private static final String DEFAULT_USER_ID = "default"`，创建会话时直接用它（`:75`），查询时如果没传 userId 也回落到它（`:387`）。
- **为什么先这样**：这是个**单机自部署的练手工具**，第一阶段的目标是把"简历→出题→面试→评估"闭环跑通、把 AI 链路做扎实；鉴权是典型的**横向功能**，早做会拖慢核心链路。这是有意识的取舍，不是漏了。
- **要怎么补（面试官问就答这个）**：① 引入 Spring Security + JWT，登录后把 userId 放进 `SecurityContext`；② **所有 Repository 查询强制带 userId 条件**（这是改造量最大的部分，`findById` 要全部换成 `findByIdAndUserId`）；③ 给 WebSocket 握手加 token 校验（现在建立连接时没有身份校验）；④ 给上传接口加限流与文件类型白名单。**②是关键，也是最容易被漏掉的——只加登录不改查询，等于越权漏洞还在。**

#### 我没有用消息中间件（Kafka / RabbitMQ）

- **为什么不用**（详见 2.6）：本项目的异步场景只有三条管道（知识库向量化、简历分析、面试评估），**特点是"低频、单机、可以接受秒级延迟、必须能查任务状态"**。Redis Stream 自带消费组和 ACK，且 Redis 本来就在架构里（缓存 + 限流），**不引入第二个中间件就等于少一份运维成本**。
- **什么时候必须换**：需要**削峰填谷**（瞬时写入量远超消费能力）、需要消息长期留存与重放、需要多团队多消费者复杂拓扑时，Redis Stream 的容量和可观测性就不够了，那时换 Kafka。

#### 只做了单体部署（没有 K8s / 没有注册中心 / 没有 CI）

- **现状**：`docker-compose` 起 6 个容器、单实例、无副本。没有 Nacos/Eureka（**只有一个服务，注册中心没有意义**），没有 K8s（**个人项目上 K8s 是纯负债**），也**没有 CI 流水线**（测试我在本地手动跑——这条我在第三章自曝过，是计划补的第一件事）。
- **什么时候该变**：出现"需要横向扩容"（那时先要解决 WebSocket 会话粘性和 Redis 缓存一致性）或"需要多人协作保证质量"（那时必须先有 CI）。

#### 两个基础配置类（被顺口问到时的**如实**回答）

- **`CorsConfig` / `CorsProperties`**：跨域配置，**这个我讲得清**。`CorsProperties.java:9-12` 用 `@ConfigurationProperties(prefix = "app.cors")` 定义 `allowedOrigins`，默认值就是 `http://localhost:5173`（Vite dev server 的默认端口）；`CorsConfig.java:24-42` 把逗号分隔的域名逐个加进白名单，允许 GET/POST/PUT/DELETE/PATCH/OPTIONS，`allowedHeaders "*"`、`allowCredentials true`、`maxAge 3600` 秒（让浏览器缓存预检结果），并且**只注册在 `/api/**` 路径上**，不把跨域策略扩散到全部路径。
  **开发环境为什么需要它**：前端 5173、后端 8080 属于跨域；生产由 Nginx 同源反代，本来就不需要——这也是我在 `frontend/src/api/request.ts` 里把 dev baseURL 写死成 `http://localhost:8080` 的另一半原因。
- **`JacksonConfig`**：**这个要如实说——它现在几乎是空的**。`JacksonConfig.java:14-17` 只做了一件事：把一个 `new ObjectMapper()` 注册成 Spring Bean，**没有任何日期格式或模块配置**（全项目也搜不到 `JavaTimeModule` / `@JsonFormat`）。
  如果面试官追问"那你的时间字段（`LocalDateTime`）怎么序列化的"，**不要硬答、不要编**，标准回答是："这块我确实没有统一约定，是个待改进点。规范做法是在 `application.yml` 里用 `spring.jackson.*` 统一配置，而不是自己 new 一个 `ObjectMapper`——因为自定义 `ObjectMapper` Bean 会让 Spring Boot 的 Jackson 自动配置失效。"
