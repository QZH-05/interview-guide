## 一、项目整体介绍

> **这一章的作用**：面试开场 3 分钟内，让面试官**听懂你在做什么**，并且相信这件事**有真实的用户痛点**。
> 背法：`1.1` 和 `1.2` 是"垫场"，讲到哪都行；`1.5` 一分钟版和 `1.6` 三分钟版**必须逐字背熟**，因为面试开场一定会用。

### 1.1 一句话定位（先说这一句，再展开）

**一个面向求职者的 AI 面试训练平台。**

用户上传简历 → AI 解析并指出问题 → 自动生成"针对这份简历"的面试题 → 用文字或**实时语音**做模拟面试 → 面试结束自动出多维度评估报告。平台还内置了知识库问答（RAG）、面试日程管理、多模型厂商配置。

**用大白话再说一遍（如果面试官不是 AI 方向，就用这三句）**：

> "简单说，它就是一个**陪你练面试的 AI 教练**。你把简历传上去，它先挑你简历的毛病，然后扮演面试官问你问题——你可以打字回答，也可以**直接对着麦克风说话，它会把你说的话转成文字、判断你有没有说完、再用语音把下一个问题问回来**，就像一个真人在跟你视频面试。面完它给你一份评分报告，告诉你哪答得好、哪答得差。"

### 1.2 用户视角的完整旅程（讲不清项目时，就按这 7 步往下走）

面试官听不懂一个项目，通常是因为**你只讲了技术名词，没讲用户经历了什么**。所以这一节是"救场话术"：按用户操作顺序讲，每步都有一句"用户看到什么"。

| # | 用户做什么 | 系统做什么 | 用户看到什么 |
|---|---|---|---|
| 1 | 注册登录，上传简历（PDF / Word / 图片） | 文件存对象存储，投一条异步任务到 Redis Stream | "上传成功，正在解析中"，页面出现进度状态 |
| 2 | 等几秒 | 异步消费者解析文档、清洗文本、调大模型做结构化抽取 + 简历打分 | 简历列表出现分数和一条条"问题项"，如"项目描述缺少量化结果" |
| 3 | 点"开始面试"，选岗位方向（Java 后端 / 算法 / 前端 / AI Agent 等） | 按 Skill 岗位手册 + 类目配额算法抽题，结合简历内容生成题目 | 进入面试房间，看到第一道题 |
| 4 | 答题（**打字**，或切到**语音模式**直接说话） | 文字模式：流式调大模型出下一题/追问；语音模式：WebSocket 收音频 → 实时识别 → 判断你讲完没有 → 生成追问 → 合成语音 | 文字：题目逐字冒出来；语音：实时字幕 + 面试官"开口说话" |
| 5 | 中途可以暂停、恢复、提前结束 | 会话状态落库，音频缓存保留，恢复时接着上一轮继续 | 暂停时麦克风自动关掉，恢复后从断点继续 |
| 6 | 面试结束 | 统一评估引擎分批调用大模型打分，**分数由代码汇总计算**，生成报告 | 技术 / 沟通 / 逻辑 / 综合四项得分 + 亮点 + 待改进 + 总结 |
| 7 | 复盘完，去看历史记录 / 用知识库问问题 | 会话历史和评估报告持久化；知识库走 RAG 语义检索 + 流式问答 | 历史列表可回看；知识库问答带引用来源 |

**这一节的一句话总结（可以直接说出来）**：

> "所以它不是一个聊天框套壳——**它是一条完整的业务闭环：简历是输入，出题是因人而异，面试是交互过程，评估是交付物。** 我做的每一个技术决策，都是为了让这条闭环在真实使用下不崩。"

### 1.4 五个最容易让面试官听不懂的词（30 秒通俗版）

讲项目时这几个词一出口，面试官就会开始判断你是不是真懂。所以**每个词的第一次出现，都要顺手带一句解释**：

| 词 | 一句话解释（口语版） |
|---|---|
| **大模型 / LLM** | 就是 GPT、通义千问这类"能对话、能写文章的 AI"。它的特点是你**没法保证它每次输出都一个格式**，这是本项目的最大麻烦来源。 |
| **Prompt 工程** | 不是写提示词那么简单，是"怎么把业务规则、参考资料、用户输入拼成一段话发给模型，并且**防住用户在里面埋指令**"。 |
| **RAG（检索增强生成）** | 让模型先"查资料"再回答。因为模型不知道你的私有文档，所以先在你上传的文档里检索出相关段落，塞进 prompt 里一起发给它，"开卷考试"。 |
| **向量检索** | 把文字变成一串数字（叫向量），意思相近的文字数字也相近，于是可以用"算距离"的方式找到语义相关的段落——**解决关键词搜索搜不准的问题**。 |
| **WebSocket** | 普通 HTTP 是"你问我答一次就断开"，WebSocket 是**一条一直握着的双向通道**，服务端可以随时主动推消息给你。语音面试必须用它，因为音频和字幕要持续双向流动。 |

### 1.5 一分钟精简版（被问"介绍一下你的项目"时用，逐字背）

> 我做的是一个 AI 面试训练平台，解决的是**求职者缺少低成本、高仿真面试练习环境**的问题——找真人模拟面试贵、约时间难，而且练完没人给你结构化反馈。
>
> 用户上传简历后，系统用大模型解析并打分，然后**由 Skill 岗位手册驱动生成针对性面试题**，可以做文字面试，也可以做**实时语音面试**：浏览器采集麦克风音频流，走 WebSocket 到后端，服务端做实时语音识别，再调用大模型生成面试官追问，最后把回复合成语音推回前端播放，整个过程支持暂停恢复、实时字幕、回声防护。面试结束自动生成多维度评估报告。
>
> 技术上有三个我个人比较满意的点：一是**单 Agent + Java 编排式流水线**的架构取舍，只有语音面试官给工具；二是**评估的可复现性设计**，固定 rubric、分批调用、算数交给代码而不是让模型算；三是**语音链路的延迟优化**，流式 LLM 配句子级并发 TTS，让面试官"边想边说"。
>
> 项目做了大约 9 个月，186 次提交，后端一万九千行，从架构设计到部署脚本都是我自己搭的。

### 1.6 三分钟详细版（面试官说"展开讲讲"时用，按 5 段说）

**第 1 段 · 背景与痛点（30 秒）**
> 面试练习这件事有三个痛点：第一，真人模拟成本高，找资深同行陪练一次很难；第二，练习完没有结构化反馈，你自己不知道哪答得差；第三，市面上的题库是静态的，跟你简历里的项目对不上，练了也没用。

**第 2 段 · 我做了什么（40 秒）**
> 所以我做了这个平台，核心链路是"简历 → 出题 → 面试 → 评估"闭环。亮点在于**面试官人设不是写死在 prompt 里的**，而是做成了可插拔的 Skill 目录：每个方向一个 `SKILL.md` 给面试官人设，一个 `skill.meta.yml` 给类目配额和参考资料映射，另有 19 份共享知识点清单。目前内置 10 个方向（Java 后端、算法、前端、AI Agent、测开、系统设计等），新增方向只需要新增一个目录，不用改代码、不用重训模型。
>
> （**术语垫一句**：这里说的 Skill 你可以理解成"岗位面试手册"——一个 Markdown 文件描述了"这个岗位的面试官是什么风格、按什么比例考哪些类目"。）

**第 3 段 · 技术架构（40 秒）**
> 后端是 Spring Boot 4 + Java 21，用了虚拟线程扛阻塞 IO。数据层 PostgreSQL + pgvector 做向量检索，Redis 做缓存、限流和异步消息队列。AI 层是 Spring AI，我自己封装了一层 `LlmProviderRegistry` 做多厂商路由和三种 ChatClient 配方：默认配方带工具、**plain 配方刻意剥掉工具专供结构化输出**、voice 配方带流式 ToolCallAdvisor。前端 React 18 + TypeScript，语音采集用 AudioWorklet 做 PCM 重采样，配客户端 VAD。
>
> （**术语垫一句**：结构化输出就是"要求模型必须返回一个固定格式的 JSON"，这样后端才能当对象解析，而不是拿到一段自由文本再拿正则去抠。）

**第 4 段 · 我的核心工作（40 秒）**
> 我主要负责三块：第一，**语音面试实时链路**，从 WebSocket 协议设计、ASR/TTS 会话管理、回声防护到句子级并发 TTS 全是我写的；第二，**出题与评估引擎**，包括确定性配额算法、历史题去重、分批评估与汇总；第三，**知识库 RAG 检索链路**，文档解析、切片、向量化、自适应检索、SSE 流式问答。

**第 5 段 · 结果与反思（30 秒）**
> 结果上，语音链路从阿里云 NLS SDK 迁到 Qwen3 实时模型后，TTS 首包延迟降到了 200 毫秒（降了约 60%），ASR 识别准确率约 95% 以上，配置项从 9 个环境变量简化到 2 个。
> 项目目前还有几个我自己记录在案的技术债，比如语音侧的阶段状态机有一段"没接线"、长面试的上下文是全量注入没有窗口、Nginx 配置里缺 WebSocket 代理的 location，这些我在后面可以详细说我的改法。
>
> **（最后一句是加分项，不是减分项：主动说出自己代码里的问题，比被问出来强得多。但一定要紧跟着给出改法，否则会变成"能力不行"。）**

### 1.7 被追问"这项目几个人做的、你具体做了多少"时的标准答法

> 这是我个人主导的开源项目。功能设计、技术选型和绝大部分代码是我写的，仓库总共 186 次提交，我的提交占 84%，剩下的是社区同学提的 PR 和问题修复。项目是我一个人从零搭起来的，所以每个模块的设计取舍我都能讲清楚——**包括哪些地方我知道做得不好、当时为什么先这么写**。

**如果面试官继续追"那你不就是照着教程做的吗"**：

> 一开始确实参考过同类开源项目的思路，但**架构上我做了几个不同于它们的决定**：一是把面试官人设抽成 Skill 文件而不是写死在 prompt 里；二是刻意剥离"带工具的客户端"专门用于结构化输出，避免工具调用污染 JSON；三是把文本面试和语音面试的评估合并成一个引擎，因为它们的 rubric 和汇总逻辑完全一样。这三条我在第四章会讲清楚为什么。
