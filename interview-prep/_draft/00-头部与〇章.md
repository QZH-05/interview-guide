# 智能 AI 面试官平台 · 面试项目全流程详解（详细版）

> **用途**：面试时讲项目的"总纲"。按章节顺序背，每章都能独立成段回答。
> **口径声明**：本文所有技术细节均来自本项目真实代码（`D:\interview-guide`）。
> 涉及性能/规模的数据分两类：**① 项目文档中已记录的实测值**（会明确标注出处）；**② 本地自测/估算值**（会标注"估算"）。凡标注估算的，面试时请务必说成"本地自测口径"，不要说成线上数据。
> **最后更新**：基于仓库 186 次提交、约 9 个月迭代后的代码状态整理。
> **配套文件**：`02-背诵速记卡.md`（数字 / 类名 / 缺陷清单，面试当天早上过一遍）、`03-面试口述稿.md`（3-5 分钟可以直接开口念的版本）。

## 这份文档怎么用（三遍读法）

| 遍数 | 读什么 | 目标 |
|---|---|---|
| 第 1 遍 | 〇章 + 第一章 + 第五章 | 能在 3 分钟内把项目讲清楚，并且**知道最该讲哪几个难点** |
| 第 2 遍 | 第二章 + 第四章 | 每个技术点都能回答"**它是什么 / 解决什么问题 / 我怎么实现的 / 代价是什么**" |
| 第 3 遍 | 第六章 + 第七章 + 第八章 | 应对"做过什么优化""你负责什么""我再追问一句" |

**背诵纪律**：本文每一节都按「**先讲这是什么 → 再讲解决什么问题 → 再讲我怎么实现（含类名/参数/行号）→ 最后讲代价与短板**」四步写。背的时候**不要只背结论**，一定要把小标题的四步结构记住——面试官追问时你是顺着这四步往下答的。

## 〇、开场前必须背下来的三句"人设纪律"

1. **绝不说"多 Agent 协作"**。这个项目没有 Agent 之间的通信、没有 planner/executor、没有共享便签。正确表述是：
   **"1 个真 Agent（语音面试官）+ N 个由 Java 严格编排的 LLM 任务流水线"**。
   为什么重要：面试官只要问一句"Agent 之间怎么传递状态"，说多 Agent 的当场就崩。
2. **回答永远带"类名 + 参数名 + 数字"**。说"我用了个限流"是减分项，说"`@RateLimit` 注解 + Redis Lua 滑动窗口，GLOBAL/IP/USER 三个维度各自独立计数"才是加分项。数字清单见《02-背诵速记卡》。
3. **主动暴露缺陷并给出改法**。这个项目有 10 余处我自己记录的已知缺陷（死代码、文档与实现不一致、降级路径不可达等）。面试里承认缺陷 + 给出方案，比装作完美得分高得多。**但注意顺序：先说"当时为什么这么定"，再说"现在的不足"，最后说"我会怎么改"。**

**额外的第 4 条口径纪律（避免被打脸）**：
4. **数字一律说成本地自测/估算**。本项目没有线上流量，任何"QPS 多少""多少用户在跑"的说法都站不住。标准句式："这个数字是我在本机用脚本测的，不是线上数据。"
