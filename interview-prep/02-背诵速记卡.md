# 面试背诵速记卡 · InterviewGuide（AI 面试官平台）

> **用途**：面试当天早上过一遍。全部是**可直接说出口的短句、数字、类名、缺陷**。
> **配套**：详细版见 `01-项目全流程详解.md`（同一个目录）。
> **口径纪律**：卡片里带「文档」的是项目文档已记录的数字；「自测/估算」是本地观测或保守推算，**被追问时必须说明口径**。

---

## 一、开场三句人设纪律（进门就定调）

1. **不说"多 Agent 协作"**。正确表述："**1 个真 Agent（语音面试官，有工具循环）+ N 条 Java 编排的 LLM 流水线**。"
2. **回答必带"类名 + 参数名 + 数字"**。说"我做了限流"没价值，说"`@RateLimit` + `rate_limit_single.lua`，滑动窗口 + 令牌桶，1 次 Redis 往返"才有价值。
3. **主动暴露缺陷并给出改法**。这比假装完美强 10 倍，也是最容易建立"做过"的信任。

| 参数 | 值 | 为什么 |
|---|---|---|

### 2.5 RAG 检索参数（**自适应，这是亮点**）

| 问题长度（去空白） | topK | minScore | 配置项 |
|---|---|---|---|
| **≤ 4 字** | **20** | **0.18** | `topk-short` / `min-score-short` |
| **≤ 12 字** | **12** | **0.28** | `topk-medium` / `min-score-default` |
| **> 12 字** | **8** | **0.28** | `topk-long` / `min-score-default` |

> 其他：分块 **`TokenTextSplitter` 默认 ≈800 tokens、按标点边界、无重叠**（注：Spring AI 2.0.0-M4 的 `TokenTextSplitter` **根本没有 overlap 参数**，所以"无重叠"是**组件能力限制**，别讲成我的设计取舍）；
> 索引 **HNSW**、距离 **COSINE_DISTANCE**、维度 **1024**（`text-embedding-v3`）；
> 流式**探测窗口 `STREAM_PROBE_CHARS = 120`**；改写历史截断 **`MAX_REWRITE_HISTORY_CHAR = 200`**；
> 检索失败兜底走 **`topK * 3`** 再 limit。

> ⚠️ **术语陷阱（已读库源码核实，务必按这个说法背）**：Spring AI 2.0.0-M4 的 pgvector 实现把 `similarityThreshold` 当作**距离上限**写进 SQL（`embedding <=> ? < ?`），而返回的 score 是 `1 - distance`。
> 所以配 **0.28 实际等价于"余弦相似度 > 0.72"**，**数值越小反而越严格**——**配置名和直觉是反的**。
> **因此不要笼统说"短查询把阈值放宽了"**。正确说法是："短查询我给了**更多候选**（topK 20），阈值那一档是 0.18；顺带说一句，Spring AI 这个阈值是按**距离上限**生效的，和名字的直觉相反，我踩过这个坑。"
> （补充：`min-score-short` 运行时取的是 yml 里的 0.18，`KnowledgeBaseQueryProperties.java:30` 里 0.25 的 Java 默认值是死代码。）

## 四、缺陷 / 短板清单（**主动讲，每条都要记住"怎么改"**）

| # | 缺陷 | 现象 | 改法 |
|---|---|---|---|
| 1 | **阶段状态机是死代码** | `shouldTransitionToNextPhase` 本应自动推进阶段，但生产靠客户端发 `start_phase`，**前端从没实现**→ `currentPhase` 只影响 UI，不约束出题 | 把阶段判断接到"每轮结束"处，并把当前阶段/目标/已问题数/剩余配额注入 prompt |
| 2 | **语音侧没有"已问问题清单"** | 文本侧有 `buildHistoricalSection` 去重，语音侧没有 → **可能重复提问** | 复用文本侧方法，把"已问摘要+阶段+配额"拼进 system prompt；把重复率做成评估指标 |
| 3 | **nginx 缺 `/ws/` location 与 Upgrade 头** | 容器部署下**语音 WebSocket 根本不被代理** | 补 `location /ws/ { proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; }` |
| 4 | **评估误用带工具的默认 client** | 违反自己定的"结构化输出不给工具"原则 | **一行改动**：评估切到 `createPlainChatClient` |
| 5 | **权重不一致** | prompt 写"加权平均"，代码是**等权平均** | 二选一，倾向在代码里实现 40/20/25/15 权重 |
| 6 | **`BatchReportDTO.overallScore` 死字段** | 定义了从没被读取，白算一次 | 删掉 |
| 7 | **鉴权失败被当解析失败重试** | `StructuredOutputInvoker` 对 401/403 也重试，白等两个往返 | 按异常类型分类：网络/解析才重试，鉴权快速失败 |
| 8 | **没有 CI** | `app/Dockerfile` 构建时 **`-x test` 跳过测试**，合并前也没人跑 | 加 GitHub Actions（build + test + 镜像） |
| 9 | **测试覆盖不均** | `resume`/`interview`/`interviewschedule` **零测试**；6 个类 `@Disabled`（48 方法从没执行）；Redisson 指着真实 Redis；无 Testcontainers | 用**「录制式 LLM 桩」**（录下真实响应做 mock）：快、可重复、不花钱；集成测试上 Testcontainers |
| 10 | **可观测性弱** | app 容器**无 healthcheck**；无 Prometheus/Grafana，只有日志 | Actuator `/actuator/health` + Micrometer → Prometheus |
| 11 | **RAG 分块无重叠** + **无 Rerank** | 跨块知识点被切断；召回后没有精排 | 加 10-15% 重叠 / 语义分块；召回后接 Rerank 只留 top 3-5 |
| 12 | **文档与实现漂移** | 语音架构文档写 400ms/1600ms，实际是 **2000/2500**；文档里的 `db/migration/` 链接**已失效**（该目录不存在） | 以 `application.yml` 为准；文档随代码更新 |
| 13 | **部署配置小坑** | `docker-compose.dev.yml` 用 **RustFS 替代 MinIO**，PG 密码默认 `123456` 与 `.env.example` 不一致；`onnxruntime-web` npm pin **1.24.3** 但运行时从 CDN 加载 **1.22.0** | 统一环境变量与版本 |

## 五、万能应答结构（任何问题都能套）

```
① 一句话结论（先说结论，别铺垫）
② 为什么这么选（对比过的替代方案 + 取舍理由）
```

- "这个问题我分两层回答，先说结论，再说为什么。"
