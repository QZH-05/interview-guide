# 2026-07-07 工作日志

## 模拟面试"创建面试失败"问题排查与修复

### 问题
用户运行项目后，模拟面试功能无法使用，前端显示"创建面试失败"。

### 根因
`LlmProviderBootstrapService` 只在 `llm_provider_config` 表为空时（`count() == 0`）才 seed Provider 数据。
用户首次启动项目时 `.env` 中的 `AI_BAILIAN_API_KEY` 是 `.env.example` 的占位符 `your_dashscope_api_key_here`，
该占位符被 AES-256-GCM 加密后存入数据库。后来用户在 `.env` 中更新了真实 API Key，但数据库中的旧加密 Key 从未更新。
创建面试时，应用从 DB 读取旧 Key 解密后调用 DashScope API → 401 → 前端显示"创建面试失败"。

### 修复
用 Python 脚本（AES-256-GCM，dev fallback key）将 `.env` 中的真实 API Key 加密后直接 UPDATE 到 `llm_provider_config` 表的 `dashscope` 记录。
验证：启动后端，调用 `POST /api/interview/sessions` 成功返回 6 道面试题。

### 附带发现
- `./gradlew bootRun` 不带 `--args` 时，Tomcat 在端口 49677 而非 8080 启动（`application.yml` 中 `server.port: 8080` 未生效）。
  原因待查（疑似 Spring Boot 4.0 的属性绑定变化或环境变量干扰）。用户从 IDE 启动可能不受影响。
  临时方案：`./gradlew bootRun --args="--server.port=8080"`。

### 关键代码路径
- Bootstrap: `LlmProviderBootstrapService.seedProvidersIfNecessary()` (@PostConstruct, 只在空表时 seed)
- 加密: `ApiKeyEncryptionService` (AES-256-GCM, dev fallback key = "interview-guide-dev-only-provider-api-key-encryption")
- 加载: `LlmProviderRegistry.loadProviderOrThrow()` (从 DB 读取并解密)
- 创建面试: `InterviewSessionService.createSession()` → `InterviewQuestionService.generateQuestionsBySkill()` → AI 调用
