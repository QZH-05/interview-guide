# eNSP 使用手册（面向本项目）

> 适用：eNSP 1.2.00.510（已安装在 `D:\eNSP`）
> 配套：`README.md`（总体方案）、`ensp/README.md`（连线与配置）、各设备 `.cfg`

---

## 0. 先看你机器的现状

| 项 | 现状 | 结论 |
|---|---|---|
| eNSP | `D:\eNSP\eNSP\eNSP_Client.exe`，v1.2.00.510 | 可直接用 |
| Wireshark | 自带 3.6.10（`D:\eNSP\Wireshark`） | 抓包没问题 |
| VirtualBox | 自带 5.2.44 | 只有 USG/AC/AP 需要 |
| WSL2 / Docker | 正在运行 | **会和 VirtualBox 5.2 冲突** |
| 环回网卡 | 尚未创建 | 需要手动加一块 |

**重要结论**：你机器上 Docker 的 WSL2 正在跑，VirtualBox 5.2 大概率起不来。
所以**不要用 USG6000V 防火墙，也不要用 AC/AP 做无线**，按主方案用
AR2220 + S5700/S3700 就够，USG 的升级方案留到换机器时再做。

## 1. 界面地图（5 分钟）

启动：双击 `D:\eNSP\eNSP\eNSP_Client.exe`（建议右键"以管理员身份运行"）。

```
┌─────────────────────────────────────────────────────────────┐
│ 菜单：文件  编辑  视图  工具  帮助                            │
├─────────────────────────────────────────────────────────────┤
│ 工具栏：[新建][打开][保存] │ [启动][停止][抓包][删除] │ [连线] │
├──────────────┬──────────────────────────────────────────────┤
│ 设备区        │                                              │
│  路由器       │              工作区（拖设备、连线）             │
│  交换机       │                                              │
│  终端         │                                              │
│  防火墙       │                                              │
│  其他设备     │                                              │
│  [搜索框]     │                                              │
├──────────────┴──────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────┘
```

**设备在哪**

| 要用的设备 | 左侧分类 | 型号 |
|---|---|---|
| R1 | 路由器 | AR2220 |
| CORE | 交换机 | S5700 |
| ACC1 / ACC2 / DMZ-SW | 交换机 | S3700 |
| PC-TEACHER / PC-B | 终端 | PC |
| DNS / ISP-PUB | 终端 | Server |
| 桥接真实主机 | 其他设备 | Cloud |

找不到就在搜索框里直接输型号。

**四个最常用的动作**

1. **拖设备**：从左侧拖到工作区。
2. **连线**：点工具栏"连线"（默认自动选择），点第一台设备的端口，再点第二台设备的端口。
3. **启动**：框选设备 → 点工具栏绿色"启动"，或右键 → 启动。
4. **进命令行**：设备图标变绿后，**双击**设备。

> 设备图标：灰色 = 关机，红色/黄色 = 启动中，绿色 = 就绪。
> 启动要等 10–30 秒，没变绿之前双击是没反应的。

## 2. 第一个实验：两台 PC 互通（10 分钟）

目的：先熟悉"拖、连、启、配、测"五件事，不碰命令行。

### 步骤

1. 拖 2 台 `PC` + 1 台 `S3700` 到工作区。
2. 点"连线"：
   - PC1 的 `Ethernet0/0/1` → S3700 的 `Ethernet0/0/1`
   - PC2 的 `Ethernet0/0/1` → S3700 的 `Ethernet0/0/2`
3. 框选三台设备 → 点"启动" → 等图标变绿。
4. 双击 PC1 → "基础配置"：
   - IPv4：`192.168.1.10`
   - 子网掩码：`255.255.255.0`
   - 网关：留空
   - 点"应用"
5. 双击 PC2 → 配 `192.168.1.11 / 255.255.255.0`。
6. 双击 PC1 → 切到"命令行"标签 → 输入：
   ```
   ping 192.168.1.11
   ```
   看到 `Reply from 192.168.1.11` 就成功了。

### 顺手认识一下 CLI

双击 S3700 → 回车 → 看到 `<Huawei>`：

```
<Huawei> system-view
[Huawei] sysname SW1
[SW1] display vlan
[SW1] quit
<SW1> save
```

- `< >` 是用户视图，`[ ]` 是系统视图。
- `quit` 退一级，`return` 直接回用户视图。
- `save` 会问 `[Y/N]`，输 `y`。

## 3. 搭本项目：分 3 个阶段，不要一次上 9 台

### 阶段一：最小闭环（约 30 分钟）

**设备**：R1 + CORE + ACC1 + PC-TEACHER（4 台）

```
PC-TEACHER ── ACC1 ── CORE ── R1
```

1. 按 `ensp/README.md` 的连线表接好这 4 台，启动。
2. 双击 ACC1，粘贴 `ensp/ACC1.cfg`。
3. 双击 CORE，粘贴 `ensp/CORE.cfg`。
4. 双击 R1，粘贴 `ensp/R1.cfg`（DNS 那两行先不用管）。
5. 验证：
   ```
   [CORE] display ip pool
   [PC-TEACHER] ipconfig
   [PC-TEACHER] ping 192.168.10.1
   [PC-TEACHER] ping 10.0.1.1
   ```
   能拿到 `192.168.10.x`，能 ping 通网关和 R1，阶段一就过了。

> 这一步先不管 DMZ、NAT、DNS。R1 的 ACL 指向一个还不存在的网段，
> 不影响内网互通。

### 阶段二：接入真实客户端（约 30 分钟）

**新增**：ACC2 + Cloud1 + PC-B

1. 接好 ACC2（上行 CORE `GE0/0/3`，下行 `E0/0/1` 接 Cloud 端口1）。
2. 粘贴 `ensp/ACC2.cfg`。
3. 双击 Cloud → 端口1 → 绑定"有线网卡"→ 端口类型 GE → 增加。
4. PC-B 用网线接到这台机器的有线网卡，设自动获取 IP。
5. 验证：
   ```
   PC-B: ipconfig          → 192.168.20.x
   PC-B: ping 192.168.20.1
   PC-B: ping 192.168.10.10
   ```

> 有线网卡在 Windows 里要**取消 IPv4**，让 eNSP 独占它。

### 阶段三：DMZ + 应用 + 抓包（约 40 分钟）

**新增**：DMZ-SW + DNS-Server + Cloud 端口2 + 环回网卡 + ISP-PUB

1. 创建环回网卡 `eNSP-Server`，配 `10.20.0.10/24`，不配网关（见第 6 节）。
2. Cloud 加端口2，绑定 `eNSP-Server`，接 DMZ-SW `E0/0/1`。
3. 接 DMZ-SW：`GE0/0/1` 接 R1 `GE0/0/2`，`E0/0/2` 接 DNS。
4. 粘贴 `ensp/DMZ-SW.cfg`。
5. 配 DNS：`10.20.0.53/24`，网关 `10.20.0.1`，加记录 `interview.local → 10.20.0.10`。
6. 接 ISP-PUB：`202.100.1.2/30`，网关 `202.100.1.1`。
7. 主机加回程路由、放行防火墙（见第 6 节）。
8. 启动 Docker Compose，验证：
   ```
   [R1] ping interview.local
   PC-B: ping 10.20.0.10
   PC-B: 浏览器打开 http://interview.local
   ```

## 4. 命令行操作（最关键）

### 4.1 进 CLI

设备变绿后**双击**，会弹出一个黑色命令行窗口。按一次回车出现 `<Huawei>`。

### 4.2 粘贴配置

1. 用记事本打开 `ensp/CORE.cfg`。
2. `Ctrl+A`、`Ctrl+C`。
3. 在 eNSP 命令行窗口里**右键 → 粘贴**（或 `Ctrl+V`）。
4. 一次粘 20–30 行，粘完等它执行完再粘下一段。

> 如果提示 `Error: Unrecognized command`，通常是 `#` 注释行或空行，
> 跳过即可；如果大量报错，说明粘太快，分段重来。

### 4.3 常用命令

| 命令 | 作用 |
|---|---|
| `system-view` | 进系统视图 |
| `sysname R1` | 改设备名 |
| `display current-configuration` | 看当前全部配置 |
| `display this` | 看当前视图配置 |
| `display ip interface brief` | 看接口 IP 和状态 |
| `display ip routing-table` | 看路由表 |
| `display vlan` | 看 VLAN |
| `display port vlan` | 看端口属于哪个 VLAN |
| `display ospf peer brief` | 看 OSPF 邻居 |
| `display ip pool` | 看 DHCP 地址池 |
| `display nat session all` | 看 NAT 会话 |
| `display mac-address` | 看 MAC 表 |
| `save` | 保存配置（输 `y`） |
| `undo xxx` | 删除某条配置 |
| `return` | 直接回用户视图 |
| `Tab` | 命令补全 |
| `?` | 帮助 |

### 4.4 忘了配置怎么办

```
<Huawei> reset saved-configuration
<Huawei> reboot
```

或右键设备 → 删除，重新拖一台。

## 5. PC / Server / Cloud 的图形配置

### PC

双击 → "基础配置"：

- IPv4 / 子网掩码 / 网关
- 勾选 DHCP 就自动获取
- 点"应用"生效

"命令行"标签里可以 `ping`、`tracert`、`ipconfig`。

### Server

双击 → "基础配置" 配 IP；再切到 "服务器信息"：

- `HttpServer`：放静态网页
- `FtpServer`：文件服务
- `DnsServer`：**开启**，添加：
  ```
  域名：interview.local
  IP：10.20.0.10
  ```

### Cloud

双击 Cloud → 配置窗口：

1. 左侧选 `Port1`
2. "绑定信息"里选网卡（**有线网卡**，不是 Wi-Fi）
3. "端口类型"选 `GE`
4. 点"增加"
5. 再选 `Port2`，绑定 `eNSP-Server`，同样增加
6. 确定

然后把 Cloud 的端口连到交换机端口。

> 绑定网卡时看不到某块网卡：以管理员身份重开 eNSP；或先在
> "网络连接"里禁用再启用该网卡。

## 6. 环回网卡、回程路由、防火墙

### 6.1 创建环回网卡

1. `Win + R` → `hdwwiz` → 下一步
2. "手动从列表安装" → 下一步
3. "网络适配器" → 下一步
4. 厂商 `Microsoft` → 型号 `Microsoft KM-TEST 环回适配器`
5. 完成后在"网络连接"里改名为 `eNSP-Server`
6. IPv4：`10.20.0.10` / `255.255.255.0`，**网关和 DNS 都留空**

### 6.2 回程路由（必须）

```powershell
# 管理员 PowerShell
route -p add 192.168.10.0 mask 255.255.255.0 10.20.0.1
route -p add 192.168.20.0 mask 255.255.255.0 10.20.0.1
route -p add 192.168.30.0 mask 255.255.255.0 10.20.0.1
```

不加会出现"TCP 能连上，但网页一直转圈"。

### 6.3 放行防火墙

```powershell
New-NetFirewallRule -DisplayName "eNSP-Demo" -Direction Inbound -Protocol TCP `
  -LocalPort 80,8080,9000 -Action Allow -Profile Any
```

## 7. 抓包

1. 右键要抓的**链路**（不是设备）→ "抓包"。
2. Wireshark 自动打开。
3. 常用过滤：

| 过滤 | 看什么 |
|---|---|
| `arp` | ARP 请求/应答 |
| `icmp` | ping |
| `tcp.flags.syn == 1` | TCP 三次握手 |
| `http` | HTTP 请求/响应 |
| `tcp.port == 80` | 80 端口流量 |
| `websocket` | WebSocket 帧 |
| `tcp.stream eq 0` | 跟踪一条 TCP 流 |

4. `File → Save As` 存成 `.pcapng`。

> 打不开 Wireshark：eNSP 菜单"工具 → 选项"里把 Wireshark 路径设成
> `D:\eNSP\Wireshark\Wireshark.exe`。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 设备一直红/黄 | 还在启动 | 等 30 秒；仍不行就删除重拖 |
| 双击设备没反应 | 没启动完 | 等变绿 |
| USG/AC 起不来 | VirtualBox 与 WSL2 冲突 | 本方案不用它们 |
| 连线连不上 | 端口类型不对 | 用"自动选择"，或换 GE/E 口 |
| 粘贴后大量报错 | 粘太快 / 注释行 | 分段粘，跳过 `#` 行 |
| PC 拿不到 DHCP | VLAN/Trunk/地址池 | `display port vlan`、`display ip pool` |
| ping 不通 | 路由/ACL/网关 | 先 ping 网关，再逐跳 |
| Cloud 看不到网卡 | 权限/网卡禁用 | 管理员运行 eNSP，禁用再启用网卡 |
| 网页转圈但能 ping | 缺回程路由 | 第 6.2 节 |
| 语音面试连不上 | nginx 没代理 /ws/ | 已修复，确认镜像已重建 |
| 抓包打不开 | Wireshark 路径未设 | 工具 → 选项 |
